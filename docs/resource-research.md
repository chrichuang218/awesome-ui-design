## 汇总结论

- 核验了 20 篇包含明确推荐或可复用设计案例的 Linux.do 帖子。
- 去重后保留 52 个网站：设计灵感平台 18 个、UI 提示词/设计工具 11 个、素材/组件资源 10 个、优秀案例网站 13 个。

- 每项都保留至少一个 Linux.do 来源帖；同一网站被多个帖子推荐时合并来源。
- 网站表已排除 GitHub 源码仓库、通用 AI 模型/开发框架、一般 Skill 市场、论坛附件/CDN、无关广告和仅用于说明业务功能的网站；设计 Skill 改在独立章节中收录。

组件框架另有 **shadcn Skill**：Linux.do 用户在[在线求好看的前端提示词与 skills](https://linux.do/t/topic/2157871)中明确建议“shadcn 搭配自家 skills”。其[官方文档](https://ui.shadcn.com/docs/skills)说明它会读取项目的 `components.json`，掌握组件搜索、安装、组合、主题与 Registry 规则。它适合已经采用 shadcn/ui 的项目，不是独立的审美生成器，因此不计入上面的 14 个设计 Skill/套件。

### 新手如何组合

- **从零做一个产品页面**：`frontend-design` 或 `ui-ux-pro-max` 选方向 → 用真实参考和内容实现 → `web-design-guidelines` 审查。
- **已有页面但很“AI”**：`Uncodixfy` / `Hallmark audit` 找套路 → `impeccable critique` 判断层级与体验 → `impeccable polish` 收尾。
- **桌面工具或后台**：优先 `app-shell-ui` 或既有组件库；不要直接套 Taste Skill 的高端营销页规则。
- **需要动效**：先用 Emil 的 `find-animation-opportunities` 判断价值；复杂时间线或滚动叙事再引入 GSAP Skills。
- **想固定某个视觉风格**：StyleKit Skill 或 DESIGN.md 负责 Token 与组件约束，再让生成型 Skill 实现。

`awesome-design-md` / GetDesign 的 **DESIGN.md** 是重要配套规范库，但它不是 Agent Skill；它负责固定颜色、字体、圆角、组件和品牌语言，不能替代 UX 结构设计。参见 [Linux.do 来源帖](https://linux.do/t/topic/1956366)与[作者仓库](https://github.com/VoltAgent/awesome-design-md)。
